1) Fatal: Logger::addRecord() (Monolog v3 signature)
<?php
namespace Lotus\Kibanablogs\Model;

use Monolog\Logger as MonologLogger;
use Monolog\Level;
use Monolog\DateTimeImmutable as MonologDateTimeImmutable;

class Logger extends MonologLogger
{
    // OLD (causes fatal):
    // public function addRecord($level, $message, array $context = []): bool

    // FIX (Monolog v3):
    public function addRecord(Level|int $level, string $message, array $context = [], ?MonologDateTimeImmutable $datetime = null): bool
    {
        return parent::addRecord($level, $message, $context, $datetime);
    }
}

2) 2–4) Deprecations: “Implicitly marking parameter … as nullable is deprecated”

Update the method signatures to use explicit nullable types.

a) __construct() – parameter $resource

Find your constructor and change the $resource parameter type to nullable:

use Magento\Framework\Model\ResourceModel\Db\AbstractDb;

// BEFORE (example):
// public function __construct(..., AbstractDb $resource = null, ...)

// AFTER:
public function __construct(..., ?AbstractDb $resource = null, ...)
{
    parent::__construct(...);
}

Keep the rest of your constructor as-is; only make $resource explicitly nullable.

3) b) setSearchCriteria()

use Magento\Framework\Api\SearchCriteriaInterface;

// BEFORE:
// public function setSearchCriteria(SearchCriteriaInterface $searchCriteria = null)

// AFTER:
public function setSearchCriteria(?SearchCriteriaInterface $searchCriteria = null)
{
    $this->_searchCriteria = $searchCriteria;
    return $this;
}

c) setItems()

// BEFORE:
// public function setItems(array $items = null)

// AFTER:
public function setItems(?array $items = null)
{
    $this->_items = $items ?? [];
    return $this;
}
